# Characterizing the Noise-Induced Divergence Depth in QAOA for MaxCut

**Authors:** Arhaan Sareen, Aditya Saxena
**Affiliation:** QSYS 2026, Institute for Quantum Computing, University of Waterloo

---

## Overview

This repository contains the full benchmark code, LaTeX manuscript, and results for our paper studying how hardware noise limits QAOA circuit depth on near-term quantum devices.

We introduce the **divergence depth** p\*(n) — the circuit depth at which hardware noise causes QAOA's approximation ratio to peak and then decline — and measure it empirically across qubit counts n ∈ {6, 8, 10, 12} and depths p ∈ {1, 2, 3, 4, 5}. We validate against real IBM quantum hardware on `ibm_fez`.

---

## Key Results

| Condition | n=6, p=1 | n=6, p=2 | n=8, p=1 | n=8, p=2 |
|-----------|----------|----------|----------|----------|
| Noiseless | 0.813 | — | 0.799 | 0.882 |
| FakeSherbrooke | 0.795 | 0.895 | — | — |
| **IBM ibm_fez (hardware)** | **0.791** | **0.871** | **0.775** | **0.804** |
| GW SDP (classical) | ~0.94 | ~0.94 | ~0.94 | ~0.94 |

Real hardware AR falls 0.022–0.033 below the calibrated noise model, with the gap growing at higher depth — directly validating the divergence depth argument.

## Running the Benchmark

```bash
python code/qaoa_benchmark.py
```

Sweeps:
- **Graph families:** 3-regular (primary), Erdős-Rényi G(n, 0.5)
- **Qubit counts:** n ∈ {6, 8, 10, 12}
- **Circuit depths:** p ∈ {1, 2, 3, 4, 5}
- **Instances:** 30 per (n, graph type) with deterministic seeds
- **Baselines:** brute-force MaxCut, greedy, Goemans-Williamson SDP
- **Hardware:** n ∈ {6, 8}, p ∈ {1, 2} on `ibm_fez` (when token is set)

Results save incrementally — safe to interrupt and resume.

| Condition | Estimated runtime |
|-----------|-------------------|
| Noiseless only | ~2–4 hours |
| + FakeSherbrooke | ~8–16 hours |
| + Hardware (n=6,8, p=1,2) | queue-dependent |
